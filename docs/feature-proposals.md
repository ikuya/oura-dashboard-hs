# 機能追加・改善の提案（2026-10-12）

コードベースを調査し、取得済みだが未活用のデータや開発上の不便を洗い出した提案。
実装順は 1 → 3 → 2 で合意。

## 優先度：高（既存データで実装できる）

### 1. 夜間 HRV・最低心拍・呼吸数チャート

`sleep_periods.data_json` には Oura の sleep ドキュメントがそのまま入っており、
`average_hrv` / `lowest_heart_rate` / `average_breath` と 5 分刻みの
`hrv` / `heart_rate` 時系列を含む。しかしフロントでも Advice でも未使用。
HRV は回復度の中心指標なので最も費用対効果が高い。

- 日次推移チャート（HRV と最低心拍の二軸、呼吸数）
- ヒプノグラムにその夜の HRV・心拍カーブを重ねる
- Advice プロンプトにも渡す

再同期もスキーマ変更も不要。

- 対応済み（2026-10-12）：夜ごとの HRV・心拍チャート（呼吸数はツールチップに表示）、
  ヒプノグラムへの HRV・心拍カーブの重ね描き、Night HRV カード、Advice への受け渡し

### 2. パーソナルベースライン比較

- 今日のスコアカードに「直近 28 日平均との差（例: +5 ↑）」
- 日次チャートに 7 日移動平均線

絶対値ではなく自分の平常値との比較で良し悪しを読めるようにする。

- 対応済み（2026-10-12）：各カードに直前 28 日平均との差、日次チャートに
  7 日移動平均の破線（凡例で元系列と一緒に切り替え）

### 3. `static/*.js` のキャッシュ問題の解消

CLAUDE.md に「ハードリロード必須」と書いている問題を実装で解決する
（yesod-static のハッシュ付き URL を ES モジュールの import に反映する、
または `Cache-Control: no-cache` を返す）。開発のたびに踏む罠なので効果が大きい。

- 対応済み（2026-10-12）：`Cache-Control: no-cache` で配信し、`staticDevel` で
  稼働中に編集したファイルも再起動なしで反映される（`Application.revalidating`）

## 優先度：中（同期対象の拡張）

### 4. タグ・ワークアウト・セッションの同期と相関表示

`enhanced_tag` / `workout` / `session` エンドポイントは未同期。
タグ（飲酒・カフェイン・遅い食事など）を取り込めば「タグがあった夜の翌日スコア
平均」を比較できる。Advice に渡せば具体的な指摘も可能になる。

### 5. 相関分析ビュー

- 就寝時刻と睡眠スコアの散布図
- 曜日別平均（平日と週末の差）

- 対応済み（2026-10-14）：就寝時刻 × 睡眠スコアの散布図（金・土の夜を色分け、
  r と回帰直線つき）と、Readiness / Sleep / Activity の曜日別平均（期間平均との差の
  棒グラフ、週末と平日の差を見出しに表示）。どちらも選択中の期間に追従する

## 優先度：低（運用面の改善）

### 6. CDN ライブラリのバージョン固定・同梱

`chart.js@4` や `luxon@3` はメジャーバージョンしか固定していない。
README の「完全にローカル」に合わせて `static/vendor/` に置き自前配信する。

- 対応済み（2026-10-14）：chart.js 4.5.1 / luxon 3.7.2 / chartjs-adapter-luxon 1.3.1 /
  marked 12.0.2 をバージョン名入りのファイル名で `static/vendor/` に同梱（npm tarball と
  同一内容、ライセンスは `licenses/`、更新手順は `static/vendor/README.md`）

### 7. Advice の定期自動生成と前回比較

日次同期後に週 1 回 Advice を生成・保存し、履歴画面で前回からの変化を見られるようにする。

- 定期生成は実装済み（2026-10-12）：`oura-advice` を cron で月水金 11:30 に実行
  （`run_advice.sh`）。前回比較は 15 で対応（2026-10-25）

### 8. 同期の鮮度警告・CSV エクスポート

- 最終同期から一定時間経過したらステータスバーで強調
- 表示中期間のデータを CSV でダウンロード

- 対応済み（2026-10-14）：ヘッダー下に最終同期からの経過時間を表示し、cron（11/17/23 時）を
  1 回逃す 13 時間超で黄、25 時間超で赤の警告に切り替える（一部のメトリックだけ遅れている
  場合はその名前を出す）。ヘッダーの CSV ボタンで表示中期間の日別データ（スコア・歩数・
  ストレス・SpO2・体温・睡眠時間/段階・夜間 HRV/心拍など）をダウンロード

# 追加提案（2026-10-25）

1〜8 の対応後に再調査した追加分。番号は上の続き。

## 優先度：高（既存データで実装できる）

### 9. Readiness の内訳（contributors）表示

`daily_readiness` の `contributors` には `activity_balance` / `body_temperature` /
`hrv_balance` / `previous_day_activity` / `previous_night` / `recovery_index` /
`resting_heart_rate` / `sleep_balance` が入っているが、チャートで使っているのは
`sleep_balance` だけ。今日のカードに「足を引っ張った上位 2 項目」を出すか、
期間中の内訳をヒートマップ（行 = 項目、列 = 日）で見せると、スコアが下がった理由が
一目で分かる。Sleep の contributors（`deep_sleep` / `latency` / `timing` など）も同様。

- 対応済み（2026-10-25）：Readiness / Sleep カードに最新日の低い上位 2 項目を表示し、
  両スコアの内訳を期間全体のヒートマップ（100 からの不足分を濃淡で表示、セルを
  タップすると値が出る）で表示。CSV にも内訳の列を追加。Readiness には
  `sleep_regularity` も含めた

### 10. ストレスと回復の対比

Stress チャートは `stress_high` だけで、`recovery_high` と `day_summary`
（restored / normal / stressful）は CSV にしか出ていない。high と recovery を
上下に分けた棒グラフにし、`day_summary` を背景色で示す。

- 対応済み（2026-10-25）：Stress チャートを高ストレス（0 より上）と高リカバリー（0 より下）の
  棒グラフにし、それぞれに 7 日移動平均を重ねた。`day_summary` が stressful の日は赤、
  restored の日は緑の背景で塗り、ツールチップにも出す。`day_summary` は実際には CSV に
  入っていなかったので `stress_day_summary` 列として追加し、Advice にも渡すようにした

### 11. Activity の詳細

Activity で使っているのは歩数だけ。`high/medium/low_activity_time`・
`sedentary_time`・`active_calories`・`inactivity_alerts` も取得済みなので、
強度別の積み上げ棒と座りすぎ時間を出す。

- 対応済み（2026-10-25）：Activity by Intensity / Sedentary Time チャートを追加。
  Low / Medium / High の活動時間（分）を積み上げ棒、座位時間（時間）を右軸の折れ線と
  7 日移動平均で表示し、`inactivity_alerts` があった日は折れ線上に赤い三角で示す。
  ツールチップに活動カロリーとアラート数を出す。CSV に強度別・座位時間（分）と
  `inactivity_alerts` の列を追加し、Advice にも渡すようにした

### 12. 翌日効果（ラグ相関）

5 の相関ビューを前日 → 翌日に広げる。前日の活動量・高ストレス時間・就寝時刻と
翌朝の Readiness / 夜間 HRV の散布図（r つき）。何をした翌日に回復が良いかが分かる。
4（タグ同期）を入れればタグの有無もここで比較できる。

- 対応済み（2026-10-26）：相関ビューの下に Next-Day Effects の散布図を追加。原因
  （前日の歩数・中高強度の活動時間・高ストレス時間、前夜の就寝時刻）と結果（翌朝の
  Readiness / 夜間 HRV）をボタンで切り替え、r と回帰直線を表示する。原因のボタンには
  選択中の結果に対するそれぞれの r を出し、どれが効いているかを一目で比べられる。
  前日の値は範囲の外（ベースライン用に読み込んだ履歴）からも取るので、範囲の初日も欠けない

### 13. 長期ビュー（月次平均・任意期間）

期間は 7〜180 日のプリセットだけだが、DB には 2020 年からのデータがある。
月次平均の推移（年単位のトレンドや季節性）と、開始日・終了日を自由に指定できる入力を追加する。

## 優先度：中

### 14. 推奨就寝時刻（`sleep_time`）の重ね描き

未同期の `/v2/usercollection/sleep_time` は Oura が推奨する就寝時間帯を返す。
Bedtime / Wake チャートに推奨帯を重ねれば、実際の就寝とのずれを確認できる。
Advice にも渡せる。

### 15. Advice の前回比較（7 の残り）

生成時に直近の `advice_history` の本文をプロンプトに添えて「前回の提案以降どう変わったか」
を書かせる。履歴画面では前回との期間平均スコアの差を見出しに出す。

- 対応済み（2026-10-25）：Advice ボタンと `oura-advice` の両方で、直前に保存された
  アドバイスを `<previous_advice>`（保存日時・分析期間つき）としてプロンプトに添え、
  「🔁 前回からの変化」の節を書かせる。アドバイスのモーダル（生成直後・履歴とも）に
  Readiness / Sleep / Activity の期間平均と、その 1 つ前のアドバイスの期間平均との差を表示

### 16. スマホのホーム画面アプリ化

確認は主にスマホで行っているので、`manifest.json` とアイコンを置いて
「ホーム画面に追加」で全画面起動できるようにする。オフライン対応は不要で、
起動導線だけ短くなる。

## 優先度：低（保守）

### 17. `static/charts.js` の分割

`charts.js` は 1,200 行近くあり、睡眠・バイタル・相関・共通部品が 1 ファイルに
混在している。`charts/sleep.js` などに分けて、9〜13 を追加しやすくする。

- 対応済み（2026-10-25）：`static/charts/` に `common.js`（Chart.js の既定値・`makeChart`・
  系列色・日付ヘルパー）、`baseline.js`、`cards.js`、`scores.js`、`sleep.js`、`vitals.js`、
  `correlation.js`、`stress.js`、`activity.js` として分け、`charts.js` は `renderAll` だけの
  入口にした。`renderAll` に直書きしていたチャートも各モジュールの関数に移した。
  同じデータで分割前と描画結果・チャート設定が一致することを確認済み

### 18. DB バックアップ

`oura.db`（147 MB）はバックアップの仕組みがない。日次同期の後に
`VACUUM INTO` で日付入りの複製を作り、古いものを世代管理で消す。
Oura 側から再取得できないデータ（Advice 履歴）を守るのが主な目的。

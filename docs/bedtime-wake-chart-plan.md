# 就寝・起床チャート 設計記録

入眠・起床時刻の推移をダッシュボードに追加する。
以下は grill インタビューで合意した設計判断の記録。

## 前提

睡眠段階チャートで追加済みの `/api/sleep_periods` が `bedtime_start` /
`bedtime_end` / `latency` / `type` を返しており、`loadData()` が期間分を
`state.sleepPeriods` に一括取得している。そのため API・DB の変更は不要。

## 図の形

浮動棒（横軸=日付、縦軸=時刻）。縦軸は反転し、上が夜・下が朝。

- 外側の薄い棒: `bedtime_start`〜`bedtime_end`（ベッドにいた区間）
- 内側の濃い棒: `bedtime_start + latency`〜`bedtime_end`（入眠〜起床）
- 図の上端の点: その日に主期間以外の期間（昼寝）がある印
- 水平破線: 表示期間の入眠・起床の中央値。凡例に値を表示

## 設計判断

| 論点 | 判断 | 理由 |
|---|---|---|
| 入眠の定義 | ベッド時刻と `+latency` の両方を重ねる | 生活リズム（寝床に入った時刻）と実際の入眠を同時に見るため |
| 起床側 | `bedtime_end` のみ | Oura に「目覚めてから寝床を出るまで」の公式フィールドが無い。phase 文字列からの推定は精度と出典が入眠側とそろわない |
| 複数期間 | 主期間を棒に、他は上端マーカー | 半数の日に複数期間がある。昼寝は入眠・起床時刻の定義から外れる |
| 主期間 | `long_sleep` →（無ければ）`late_nap` 以外の `time_in_bed` 最長 | 段階チャートの既定タブと同じルール。`helpers.js` の `mainPeriod()` と `Advice.hs` の `mainSleepPeriod` で二重実装 |
| `late_nap` のみの日 | 主期間なし（棒を描かず昼寝マーカーのみ） | 実データ 2026-08-24 で 53分の夕方の仮眠が「夜」として描かれ、縦軸が 17:00 まで広がった。ヒプノグラムはこの日 `late_nap` を表示するようフォールバック |
| 縦軸の範囲 | 主期間から自動、上下 30 分の余白を目盛り刻みに丸める | 固定範囲だと普段の夜が図の半分に縮む。刻みに揃えないと端に余分な目盛りが出て隣と重なる |
| 昼寝マーカーの位置 | 上端に一列（時刻を表さない） | 実時刻に置くと昼寝が軸を広げる |
| 参照線 | 中央値 | 飲み会・旅行などの外れ値に引っ張られにくい |
| タイムゾーン | 記録地の壁時計（文字列の `HH:MM`） | 旅行時もその土地での生活リズムとして読める。ヒプノグラム（ブラウザのローカル時刻）とは旅行時のみずれるが今回は触らない |
| 0時またぎ | 正午起点の経過時間（12:00 未満は +24h） | 夜→朝が連続した数値になる |
| 配置 | Sleep Stage Duration の直後・全幅 | 睡眠系の図がまとまり、日付の x 位置が揃う |
| Advice 連携 | 日別行に `bedtime_start` / `sleep_onset` / `bedtime_end`（HH:MM）と `naps` / `nap_time_in_bed` を追加 | 就寝時刻の不規則さがプロンプトに一度も入っていなかった |

# 睡眠段階チャート 設計記録

Oura の睡眠段階（Deep / Light / REM / Awake）の推移をダッシュボードに追加する。
以下は grill インタビューで合意した設計判断の記録。

## 前提の確認（実測）

既存の `daily_metrics` の `sleep` 行には段階の時系列が無い（`score` と
`contributors` の「スコア」のみ）。段階データは別エンドポイント
`GET /v2/usercollection/sleep`（Sleep Period ドキュメント）にある。

OpenAPI spec 1.37 と実データで確認した要点:

| 事実 | 値 |
|---|---|
| `sleep_phase_5_min` | `"4442111122..."`、`1`=deep `2`=light `3`=REM `4`=awake、5分刻み |
| 文字列長 | `time_in_bed / 300` と誤差0〜1で一致 → `bedtime_start` 起点で時刻に対応する |
| `deep+light+rem` | `total_sleep_duration` に一致。`+awake_time` で `time_in_bed` に一致 |
| `type` | `long_sleep` / `sleep` / `late_nap` / `rest` / `deleted` |
| 1日あたり期間数 | 直近30日で 1期間=15日, 2期間=9日, 3期間=4日, 5期間=1日 |
| `long_sleep` が無い日 | 直近30日で 0日 |
| 全履歴取得 | 2020-08-12〜2026-07-17 で 6ページ / 4042レコード / 10.8MB / 14秒 |
| 範囲制限 | heartrate のような30日窓制限は無い（1レンジで全履歴が取れる） |

## 図の形

**2枚**を追加する。

1. **ヒプノグラム**（1晩）— 「睡眠中の推移」の直接の答え
2. **日別積み上げ棒**（期間全体）— 日をまたぐ傾向

どちらも同じ `/api/sleep_periods` から描く。

## 設計判断

| 論点 | 判断 | 理由 |
|---|---|---|
| 保存先 | 新テーブル `sleep_periods` | 1日に複数期間があるため `daily_metrics` の `UNIQUE(metric, day)` に収まらない。heartrate と同じ「専用テーブルを持つ sync ターゲット」の前例に倒す |
| 書き込み | Oura の `id` をキーに `INSERT OR REPLACE` | 削除的な操作を持たない。API が空を返しても既存データが消えない。ユーザーが消した睡眠は `type: "deleted"` の墓標として届くので読み出し時に除外できる |
| 表示対象 | `deleted` / `rest` を除外 | `rest` は「寝ていない」とユーザーが否認した区間で、Oura の日次スコアにも寄与しない |
| ヒプノグラムの横軸 | 1期間分のみ（`long_sleep` 既定、他はタブ切替） | 全期間を実時刻軸に載せると横軸15時間になる日があり本睡が潰れる（実データで確認） |
| API の粒度 | 必要フィールドのみ | 生レコードだと180日で約900KB。必要分だけなら約160KB。DB には生レコード全体を保存するので、後からフィールドを増やしても再 sync は不要 |
| フェッチ | `loadData()` で期間一括取得、日選択はクライアント側 | ネットワーク往復ゼロで `‹ ›` が動く。遡れる範囲は選択中の期間（7d/14d/…）に一致する |
| 初回バックフィル | `defaultStart`（2020-01-01）から全履歴 | 他メトリクスと同じ扱いになり `findMissingRange` をそのまま使える。実測14秒 |
| 描画方式 | `stepped: "after"` の line ＋ `segment.borderColor` | 新規 CDN 依存を増やさない。phase コード `1..4` をそのまま y 値にすると Deep が下・Awake が上になり Oura アプリと同じ並びになる |
| 積み上げ棒 | Deep/Light/REM/Awake の4段・時間単位 | 棒の高さが `time_in_bed` に一致し、中途覚醒の多い夜が一目で分かる |
| phase フィールド | `sleep_phase_5_min` | `app_sleep_phase_5_min` は docs に「移行期間後に削除予定」とある。DB には両方入るので API 側で切り替えられる |
| Advice 連携 | 日別集計秒数のみ追加 | 実際の睡眠時間が今まで一度もプロンプトに入っていなかった。phase 文字列はトークンの無駄なので渡さない |

## 承知している割り切り

- 積み上げ棒（`*_duration` フィールド由来）とヒプノグラム（5分量子化）の段階時間は
  数%ずれる。例: 2026-07-17 の Deep は 3030s に対し phase 文字列からは 3300s。
  出典が異なるため一致させない。
- `sleep_phase_5_min` を使うため Oura アプリの表示とは約15%のエポックで差が出る
  （直近30日・2718エポック中409個）。
